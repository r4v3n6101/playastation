# HashMap baseline — 2026-11-16

Measured on the policy/benchmark implementation committed with this report,
based on the separate policy commit `8f557a3`. Cache: `hashbrown 0.17.1` with `fnv 1.0.7`.

- Apple M4, 10 physical/logical cores, 16 GiB RAM.
- macOS 27.2.1, build 26B131; `aarch64-apple-darwin`.
- `rustc 1.99.0-nightly (c4af71034 2026-07-06)`, LLVM 22.1.8.
- Criterion 0.8.2, bench/release defaults; no custom RUSTFLAGS or CPU pinning.
- 50 samples, 1 s warm-up, 3 s measurement per case; cases run sequentially.
- `cpu.rs` SHA-256: `e2a03760a8616a4e5b2124a95783c9014fd73c22954eb471a90b466b65b153fc`.
- `support/mod.rs` SHA-256: `4588ec018e5be3f56ea4a9bc06f6549542d878773be33961e85c51f0ee145e79`.

Command: `cargo bench -p playastation --bench cpu --locked --offline -- --save-baseline hashmap`.
This run used `CARGO_TARGET_DIR=/private/tmp/playastation-policy-bench-target`.
Full Criterion samples remain in that directory; the estimates and 95% confidence
intervals are saved in [the CSV](hashmap-2026-11-16.csv).

Time is microseconds per complete guest program pass. The table uses Criterion's
slope estimate (the same estimator as the console output). Speedup is
`interpreter time / cached time`; below 1 means that cached execution is slower.

These numbers cover the synthetic CPU/cache workloads described in
[the benchmark README](../README.md). They do not estimate game FPS or BIOS boot time.
Cold execution includes decoding/insertion but excludes engine construction and destruction.
Repeated code-page stores continuously invalidate blocks, even in the warm case.
Small differences require another run on the same machine; this is one baseline run.

Validation: 19 core unit tests passed, all 24 Criterion smoke cases passed,
and the no_std core checked for `wasm32-unknown-unknown`.

The separate [allocation measurements](hashmap-memory-2026-11-16.csv) include
decoded blocks, index and page tracking. For `dispatch_4096`, the live heap
after the pass is 888984 bytes; after clearing, 167960 bytes of capacity remain.
The allocation counter is not linked into the timing benchmark.
